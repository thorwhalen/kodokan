kodokan.quiz#

Quiz service: the UI-agnostic orchestrator of the technique-recognition game (app #6).

flashcards makes and scores one problem, learning chooses the next one from a learner’s history. This module wires them to storage so that any surface (a web app, a CLI, a test) needs only three calls, all taking and returning plain data:

quiz = Quiz(catalog, similarity=similarity)          # or Quiz.from_library()
problem = quiz.next_problem("ana", strategy="sm2")   # issued problems are remembered
record = quiz.submit(problem.problem_id, chosen_index=2, response_time_ms=3100)
quiz.stats("ana")                                    # per-technique {n, wrong, ...}

State lives in two dict-like stores (seams; default: dol JSON files under the data root, one per user prefix): the issued problems not yet answered, and the responses (one record per answered problem, the learning.RECORD_FIELDS schema). A surface can therefore be stateless between “give me a problem” and “here is the answer”.

>>> catalog = {k: {"name": k.title(), "clips": []} for k in ("seoinage", "ogoshi", "tomoenage", "uchimata")}
>>> quiz = Quiz(catalog, responses={}, problems={})
>>> problem = quiz.next_problem("ana", rng=__import__("random").Random(0))
>>> record = quiz.submit(problem.problem_id, problem.correct_index)
>>> record["correct"], record["user"], quiz.stats("ana")[problem.target_key]["n"]
(True, 'ana', 1)

Bases: object

The game for one catalog (technique_key -> {"name", "clips"}).

Parameters:

  • similarity (dict | None) – target -> {key: weight}, e.g. flashcards.build_confusability(); the learner’s own confusion is merged on top by the strategy.

  • responses (MutableMapping) – answered-problem records, keyed <user>__<ts>__<response_id>.json.

  • problems (MutableMapping) – issued, unanswered problems, keyed <problem_id>.json. Both default to quiz_stores().

  • clip_for (object) – key -> clip for the media of a technique (default: its first clip).
