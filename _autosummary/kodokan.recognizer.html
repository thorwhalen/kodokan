kodokan.recognizer#

Technique recognition for applications: top-k guesses with inspectable scores (#3).

kodokan.recognize holds the research tools (features, LOO evaluation, metrics). This module is the application facade over them:

  • TechniqueRecognizer — fit on pooled demo descriptors, then recognize() returns a Recognition: the top-k Guess es and the score of every technique (the intermediate vector a UI

    can show).

  • recognize_segments() — offline video: detect the throws in a whole pose sequence and recognize each.

  • ThrowDetector — a rolling pose buffer that reports each throw once its segment has closed; LiveRecognizer recognizes them (live stream mode).

Scores are a softmax over negative distances to each technique’s centroid, in the train-standardized (and, when scikit-learn is installed, LDA-projected) descriptor space, with distances in units of the typical within-technique spread (measured leave-one-out, as a held-out demo would see it). They rank techniques and sum to 1; they are not calibrated probabilities. The LDA projection is still fit on every training demo, so with few demos per technique the spread stays optimistic.

>>> rng = np.random.default_rng(0)
>>> X = np.vstack([rng.normal(c, 0.3, size=(5, 4)) for c in (0.0, 3.0, 6.0)])
>>> y = np.repeat(["seoi-nage", "o-goshi", "uchi-mata"], 5)
>>> rec = TechniqueRecognizer(method="centroid").fit(X, y)
>>> r = rec.recognize(np.full(4, 3.1), k=2)
>>> r.guesses[0].technique, len(r.guesses), round(sum(r.scores.values()), 6)
('o-goshi', 2, 1.0)

class kodokan.recognizer.ThrowDetector(*, fps, width=0, height=0, buffer_s=20.0, close_after_s=1.0, segmenter=<function motion_segments>)[source]#

Bases: object

A rolling pose buffer that reports each throw once, after its segment closes.

Push one frame at a time ((P, 17, 3) keypoints, as in PoseSequence). push() returns (buffer, segment) for the throws that closed with that frame. A segment counts as closed when it ends at least close_after_s before the newest frame; the buffer keeps the last buffer_s seconds of pushed frames (at fps frames a second: push every analysed frame, or pass the analysed rate as fps). A segment that mostly overlaps a throw already reported is that throw.
